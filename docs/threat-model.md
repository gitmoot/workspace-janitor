# Threat model (Linux)

This guide describes the implemented boundaries, not a guarantee against a hostile host. See [policy](policy-reference.md), [privacy](privacy.md), and [recovery](recovery.md).

## Trust and authority

The operator controls policy, discovery roots, approvals, and explicit confirmed actions. Repository contents, directory names, symlinks, Git metadata, service/process observations, provider binaries, and Jev answers are **not** authority to delete. The deterministic safety engine makes the mutation decision; `plan` cannot mutate, and `watch` only inventories. An action requires a stored plan, individual approval, current scan/policy binding, fresh target observation, and confirmed execution. The effective state and quarantine directories and built-in credential protections cannot be unprotected by policy. Generic cleanup is a same-filesystem quarantine rename; irreversible expiry requires its own policy opt-in, elapsed retention, fresh complete checks, and a separate confirmed invocation. Official provider prune is a distinct, explicitly configured irreversible path, not generic deletion.

The local account, kernel, SQLite state and journal, configured filesystem, and chosen provider executable are trusted for their respective operations. Protect the state/config directories from other users, review policies and generated services before use, and keep backups independently of quarantine. A privileged or compromised same-user process can tamper with files, the database, or the executable; janitor is not a sandbox or backup system.

## Attack surfaces and defenses

| Threat | Implemented behavior | Residual risk / operator response |
| --- | --- | --- |
| Symlinks and path traversal | Scans use explicit roots and bounded traversal; unresolved/out-of-root symlinks fail safety. Linux rename, expiry and Git metadata capture/restore open each parent component from `/` without following symlinks, then use descriptor-relative operations. Manifest installation uses an anchored no-replace rename. | Manifest staging/readback and directory sync still use path-based APIs; keep the private state tree out of other writers' reach. A competing writer can move an already-open directory; the janitor lock does not stop that writer. Recheck roots, mounts and unexpected symlink evidence. |
| TOCTOU and replaced targets | Apply checks scan and policy binding, recollects and re-evaluates guards, compares identity/fingerprint and an open handle, then uses Linux anchored operations. | Other software may race or modify contents after observation; failed revalidation is a stop, not authority to force a move. Review and re-scan. |
| Malicious repositories | Dirty/unpublished/unverifiable Git state, locks, collector failures, and linked-worktree uncertainty protect work. Git subprocesses use bounded argv, isolated HOME/global config, and `git -c` overrides that disable `core.fsmonitor` and ordinary hooks even on Git versions predating environment-based config overrides. | This is not a Git sandbox: other repository config or an operator-selected executable may still affect Git behavior. Scan untrusted repos under a constrained account; do not run provider prune against an untrusted binary. |
| Command injection | Mutations do not construct a shell command from entry names. Official provider prune requires an exact configured absolute `uv`/`npm` binary, dedicated cache, preview, and confirmation; its child environment is stripped of inherited credentials and set offline. | An operator-chosen malicious binary can still run code; offline flags are not a network sandbox. |
| Secret leakage | Jev is off by default. The opt-in daily advisory reads only `OPENROUTER_API_KEY` from an owner-only, no-follow regular file at run time; watch/cycle remain credential-free and offline. Only ambiguous entries' allowlisted, redacted metadata is sent, not contents, absolute roots, Git remotes, branch names, or symlink targets. | Names, counts and root-relative metadata may identify private work despite redaction. A private report and provider usage remain in the owner-only database. Keep it and manual `--jev-debug`/dry-run output private; see [privacy](privacy.md). |
| Automatic advisory spend and references | A successful same-day cycle and one durable daily claim precede calls. Every HTTP attempt, including retries, reserves against 7 attempts, 140 entry-offers, 100000 estimated input tokens and $0.01 estimated input cost before sending. A post-reservation transport check and UTC-midnight request deadline refuse new-day sends on the old day's claim. Interrupted reports read the reservation ledger and mark provider usage unknown. Failed/partial global references, including Gitmoot's ledger and unproven systemd aliases, block advice for all entries; proven aliases reuse an already-scanned unit without duplicate references. | Token estimation and published pricing can differ from billed usage, and a crash after a response may leave actual usage unknown. The transport check and deadline narrow but cannot make wall-clock observation and remote receipt atomic. Check the provider ledger after the first live pass; a successful HTTP response is not exact billing proof. |
| Watcher event and database amplification | In-place events on unchanged, explicitly protected top-level directories are coalesced into at most one hourly full scan; new/removed/replaced entries and overflow still reconcile. Each successful scan retains the newest 256 snapshots plus audit-referenced and last deep-size scans; `history --confirm` can trim an existing backlog. No plan, action, cycle, advisory attempt or usage record is deleted. | Protected-directory metadata can be stale for up to an hour; real changes and overflow still create scans. SQLite retains freed pages until a separately verified offline compaction with a durable read-back-verified backup and all writers stopped. History count is not a hard byte bound because pinned scans can grow; monitor disk and audit-reference rates. |
| Concurrent writers | Confirmed Linux apply/restore share a process lock; occupied destination/source names and changed identities refuse rather than overwrite. Active references/unknown observations protect paths. | The lock coordinates janitor instances, **not** editors, Git, providers, or another user/process. Stop writers and obtain a fresh plan, rather than bypassing a refusal. |
| Partial failures | Per-action durable SQLite transitions and quarantine manifests record moves. Repeating a confirmed apply can reconcile an interrupted batch; restore can recover completed moves or cancel an unmoved prepared receipt. | A disk failure, corrupt DB/manifest, tampered tree, or crash still needs manual investigation and backups. Never delete a questionable quarantine object to clear an error; follow [recovery](recovery.md). |

Automatic expiry requires both `retention.delete_enabled` and `prevention.auto_expire`, and invokes the guarded expiry path; a timer is not installed or started by the policy file. These controls reduce accidental damage, but do not establish safety against a hostile administrator, compromised kernel, remote filesystem semantics, or all same-user adversaries.
