# Threat model (Linux)

This guide describes the implemented boundaries, not a guarantee against a hostile host. See [policy](policy-reference.md), [privacy](privacy.md), and [recovery](recovery.md).

## Trust and authority

The operator controls policy, discovery roots, approvals, and explicit confirmed actions. Repository contents, directory names, symlinks, Git metadata, service/process observations, provider binaries, and Jev answers are **not** authority to delete. The deterministic safety engine makes the mutation decision; `plan` cannot mutate, and `watch` only inventories. An action requires a stored plan, individual approval, current scan/policy binding, fresh target observation, and confirmed execution. The effective state and quarantine directories and built-in credential protections cannot be unprotected by policy. Generic cleanup is a same-filesystem quarantine rename; irreversible expiry requires its own policy opt-in, elapsed retention, fresh complete checks, and a separate confirmed invocation. Official provider prune is a distinct, explicitly configured irreversible path, not generic deletion.

The local account, kernel, SQLite state and journal, configured filesystem, and chosen provider executable are trusted for their respective operations. Protect the state/config directories from other users, review policies and generated services before use, and keep backups independently of quarantine. A privileged or compromised same-user process can tamper with files, the database, or the executable; janitor is not a sandbox or backup system.

## Attack surfaces and defenses

| Threat | Implemented behavior | Residual risk / operator response |
| --- | --- | --- |
| Symlinks and path traversal | Scans use explicit roots and bounded traversal; unresolved/out-of-root symlinks fail safety. Linux rename, receipt metadata and expiry open every parent component from `/` without following symlinks, then mutate by descriptor with no-replace or anchored deletion. | A competing writer may move an already-open directory; the janitor lock does not stop that writer. Recheck roots, mounts and unexpected symlink evidence. Do not approve uncertain paths. |
| TOCTOU and replaced targets | Apply checks scan and policy binding, recollects and re-evaluates guards, compares identity/fingerprint and an open handle, then uses Linux anchored operations. | Other software may race or modify contents after observation; failed revalidation is a stop, not authority to force a move. Review and re-scan. |
| Malicious repositories | Dirty/unpublished/unverifiable Git state, locks, collector failures, and linked-worktree uncertainty protect work. Git subprocesses use bounded argv, isolated HOME/global config, and command-scope overrides that disable `core.fsmonitor` and ordinary hooks even when a repository enables them. | This is not a Git sandbox: other repository config or an operator-selected executable may still affect Git behavior. Scan untrusted repos under a constrained account; do not run provider prune against an untrusted binary. |
| Command injection | Mutations do not construct a shell command from entry names. Official provider prune requires an exact configured absolute `uv`/`npm` binary, dedicated cache, preview, and confirmation; its child environment is stripped of inherited credentials and set offline. | An operator-chosen malicious binary can still run code; offline flags are not a network sandbox. |
| Secret leakage | Jev is off by default. If enabled, only ambiguous entries' allowlisted, redacted metadata is sent; not contents, absolute roots, Git remotes, branch names, or symlink targets. | Names and counts can still be sensitive; `--jev-debug` and dry-run output must be handled as potentially sensitive. See [privacy](privacy.md). |
| Concurrent writers | Confirmed Linux apply/restore share a process lock; occupied destination/source names and changed identities refuse rather than overwrite. Active references/unknown observations protect paths. | The lock coordinates janitor instances, **not** editors, Git, providers, or another user/process. Stop writers and obtain a fresh plan, rather than bypassing a refusal. |
| Partial failures | Per-action durable SQLite transitions and quarantine manifests record moves. Repeating a confirmed apply can reconcile an interrupted batch; restore can recover completed moves or cancel an unmoved prepared receipt. | A disk failure, corrupt DB/manifest, tampered tree, or crash still needs manual investigation and backups. Never delete a questionable quarantine object to clear an error; follow [recovery](recovery.md). |

Automatic expiry requires both `retention.delete_enabled` and `prevention.auto_expire`, and invokes the guarded expiry path; a timer is not installed or started by the policy file. These controls reduce accidental damage, but do not establish safety against a hostile administrator, compromised kernel, remote filesystem semantics, or all same-user adversaries.
