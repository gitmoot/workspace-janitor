# Contributing and security reports

Changes that affect mutation or privacy need a clear operator-visible safety contract. Start from [the threat model](threat-model.md), [policy reference](policy-reference.md), [privacy guide](privacy.md), and [recovery guide](recovery.md). Keep deterministic safety authority separate from recommendations, and preserve the default of no Jev outbound request and no generic deletion. A policy or advisor must never override a protected path, uncertain observation, or stale approval.

For a contribution, explain the scenario, expected decision and observable before/after behavior in the pull request. Use a disposable fixture home and explicit roots/config/state/cache paths; point process/service/Git probes at fixtures. Do not scan your real home, Gitmoot state, credentials, or repositories for a test. A retained test should fail for a plausible safety regression and assert the user-visible contract, not source text or incidental wording. Document any changed CLI flags, policy defaults, outbound data, irreversible action, recovery path, and platform limit. For performance claims, disclose input size, hardware, I/O scope and measurement procedure; do not invent results. Run relevant checks before requesting review, and do not present an unrun check as passed.

For a suspected vulnerability, **do not post secrets, exploit payloads, private repository paths, or identifying logs in a public issue or PR**. Use the repository's private GitHub vulnerability-reporting/security-advisory channel if it is available. If that channel is unavailable, open a minimal public issue asking maintainers for a private reporting route, without exploit details. Include affected version/commit, the boundary crossed, an isolated synthetic reproducer, expected vs observed behavior, impact, and a safe contact path in the private report. Preserve local evidence, stop any affected confirmed mutation, and rotate exposed credentials through your own incident process. This document does not claim a private mailbox or a response SLA.
